Every proof is checked against a verification key. Anyone who knew the secret behind a key could forge proofs for it. A ceremony makes that secret impossible to know. This page says how the Palliora DeFi keys were made and how you can check that the contracts use them.

## What a Phase 2 ceremony does

Palliora DeFi uses Groth16 proofs. Each circuit needs its own proving key and verification key. A Phase 2 ceremony makes those keys from shared starting parameters.

Contributors take turns. Each one mixes fresh secret randomness into the keys and then destroys it. The ceremony coordinator checks every step, so a bad contribution is rejected.

The keys are safe if at least one contributor destroyed their randomness. You do not have to trust any one person. You have to trust that every contributor did not collude, and one honest contributor is enough.

## The circuits

| Circuit                                  | What it proves                                                      | Public inputs |
| ---------------------------------------- | ------------------------------------------------------------------- | ------------- |
| `register`                               | A wallet owns a shielded address                                    | 6             |
| `treeUpdate`                             | A batch of queued commitments joins the commitment tree             | 64            |
| `transact21`, `transact22`, `transact23` | A private transaction that spends up to 2 notes and makes 1, 2 or 3 | 12            |
| `transact42`, `transact44`               | A private transaction that spends up to 4 notes and makes 2 or 4    | 12            |
| `transact82`, `transact84`               | A private transaction that spends up to 8 notes and makes 2 or 4    | 12            |

The names show the shape. In `transact42`, 4 is the most notes it can spend and 2 is the number of notes it makes. See [Shielded transactions](/defi/learn/concepts/shielded-transactions).

## Where the keys are used

Ethereum and HyperEVM use the same keys. Each network has nine verifier contracts, one for each circuit, and the HyperEVM contracts have the same bytecode as Ethereum's. Their addresses are in the Verifiers tables of [Network reference](/defi/reference/network-reference).

## Verify the deployed verifiers

The second listing is the check. It needs [Foundry](https://getfoundry.sh) for `cast`, and Python 3.

```python
#!/usr/bin/env python3
"""Check that each verifier embeds the delta point of its ceremony key."""
import json, subprocess, sys

rpc, manifest_path, verifiers_path = sys.argv[1:4]
manifest = json.load(open(manifest_path))
verifiers = json.load(open(verifiers_path))  # {"VerifierRegister": "0x...", ...}

ok = True
for name, delta in manifest.items():
    code = subprocess.check_output(
        ["cast", "code", verifiers[name], "--rpc-url", rpc], text=True
    ).strip().lower()
    # A value is stored padded to 32 bytes, or without its leading zeros.
    found = all(format(int(delta[k]), "x") in code for k in ("deltax1", "deltax2"))
    print(f"{name:20} {'match' if found else 'MISMATCH'}")
    ok = ok and found
sys.exit(0 if ok else 1)
```

Save the verifier addresses from the Verifiers table of the network you check in [Network reference](/defi/reference/network-reference) as `verifiers.json`, with the same names as in the manifest. The row for "Transact 2 in, 1 out" is `VerifierTransact21`, and so on. Then run the check.

```bash
python3 check_verifiers.py https://ethereum.publicnode.com \
  ceremony-manifest.json verifiers.json
```

Every line should end in `match`. On 2026-10-16, all nine verifiers matched on Ethereum and all nine matched on HyperEVM.

This shows that the contracts hold the delta points in the manifest. To check the manifest against the ceremony, export the verification key from each final key and compare. In the exported file, `deltax1` is `vk_delta_2[0][1]` and `deltax2` is `vk_delta_2[0][0]`.

```bash
snarkjs zkey export verificationkey register_final.zkey register_vk.json
```

## Test networks

HyperEVM testnet does not use this ceremony. Its verifier keys were generated locally by one contributor, so the secret behind them is known. Anyone can forge a proof there. Use the test network only to test, and never mix its keys with mainnet's.

See [Security and audits](/defi/reference/security-and-audits) for what else has been reviewed.
